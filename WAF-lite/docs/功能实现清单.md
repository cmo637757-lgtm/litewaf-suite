# LiteWAF-NGX 功能实现清单

更新时间：2026-07-01

## 已实现功能

- 项目分支与模块整合：已在 `dev` 分支统一 A/B/C 成员代码，Nginx 模块、B 规则引擎、C 测试与统计脚本可以在同一构建链路中运行。
- Nginx HTTP 模块接入：`ngx_http_lite_waf_module` 已注册到 `NGX_HTTP_ACCESS_PHASE`，可在访问阶段执行 IP 控制、动态封禁、规则检测和审计日志。
- 配置指令：已实现 `lite_waf`、`lite_waf_trust_proxy`、`lite_waf_deny_status`、`lite_waf_blacklist`、`lite_waf_whitelist`、`lite_waf_rule_file`、`lite_waf_score_threshold`、`lite_waf_dynamic_block`、`lite_waf_max_requests`、`lite_waf_window`、`lite_waf_block_duration`、`lite_waf_log_path`。
- IP 访问控制：支持 IPv4 CIDR 黑名单和白名单，白名单优先放行，黑名单命中后返回配置的拒绝状态码。
- 可信代理取源地址：启用 `lite_waf_trust_proxy` 后可从 `X-Forwarded-For` 首个有效 IPv4 地址提取真实客户端 IP。
- B 规则引擎：已实现独立 C API，包含规则文件加载、规则行解析、请求上下文规范化、字符串匹配、PCRE2 正则匹配、分类计分、阈值决策、立即阻断和日志型规则动作。
- 检测区域：规则支持 `URL`、`ARGS`、`BODY`、`HEADERS`、`COOKIE`、`USER_AGENT`、`FILE_EXT` 区域；Nginx 模块当前接入 URI、查询参数、真实 POST/JSON 请求体、Cookie、User-Agent、部分头部和文件扩展名。
- 默认规则集：`conf/litewaf_rules.conf` 已提供 SQL 注入、RFI、目录穿越、XSS、编码绕过、危险上传扩展名、扫描器 User-Agent 等 21 条 MVP 规则。
- 动态封禁：已迁移到 Nginx shared memory zone，多个 worker 共享同一份漏桶 IP 状态表；`lite_waf_max_requests` 表示桶容量，`lite_waf_window` 表示桶从满到空的泄漏周期，超过容量后在 `lite_waf_block_duration` 秒内拒绝请求。
- 审计日志：命中黑名单、动态封禁、规则阻断或阈值阻断时写入 JSON Lines 格式日志，字段包括时间、客户端 IP、方法、URI、原因、规则、区域、分类、分值、状态码和处理耗时；字符串字段已实现 JSON 转义，避免引号、反斜杠和控制字符破坏日志结构。
- 测试脚本：`tests/test_rule_engine.c` 覆盖 B 规则引擎加载与攻击样本评分；`scripts/run_waf_tests.sh` 覆盖正常请求、SQLi、XSS、目录穿越、扫描器 UA 和动态封禁；`scripts/run_waf_post_body_tests.sh` 覆盖真实 POST 表单与 JSON BODY；`scripts/run_waf_multiworker_tests.sh` 覆盖 4 worker 共享动态封禁；`scripts/run_waf_leaky_bucket_tests.sh` 覆盖漏桶泄漏恢复行为，避免退回固定窗口；`scripts/run_waf_reload_tests.sh` 覆盖规则新增、reload 生效、规则移除后的行为回退；`scripts/run_waf_volume_tests.py` 提供 400 条批量安全/正常样本回归；`scripts/run_waf_load_tests.sh` 使用 ApacheBench 执行并发压测；`scripts/run_waf_soak_tests.py` 执行正常/攻击混合的持续流量测试；`scripts/calc_metrics.py` 计算 TP/TN/FP/FN、检测率、误报率和准确率。
- Docker/CI 自动化：已提供 `Dockerfile`、`.dockerignore`、`docker-compose.yml` 和 `.github/workflows/ci.yml`；容器镜像可在 Debian Linux 环境中自动安装依赖、下载 Nginx 1.31.1、静态编译模块并执行最终验收。
- Nginx 环境准备：`scripts/prepare_nginx_env.sh` 可幂等准备 Nginx 源码树、基础回归、容量回归、reload 和 soak 测试运行目录，并生成带绝对规则/日志路径的临时配置。
- 构建工具：`Makefile` 支持本地编译 B 规则引擎测试、命令行评估工具和清理产物。
- 注释规范：核心头文件、规则引擎实现、Nginx 模块入口和关键函数均采用 Doxygen/Javadoc 风格注释，覆盖参数、返回值和模块职责。
- 本机校验：B 规则引擎单元测试通过；Nginx 1.31.1 临时源码树模块增量编译通过；`nginx -t` 通过；最终验收脚本 `scripts/run_final_acceptance.sh` 通过；基础端到端 65 条样本 TP=25、TN=40、FP=0、FN=0；reload 回归 3/3 通过，TP=1、TN=2、FP=0、FN=0；批量回归 400 条样本 TP=200、TN=200、FP=0、FN=0；真实 POST BODY 回归 8/8 通过，TP=6、TN=2、FP=0、FN=0；4 worker 共享动态封禁回归 10/10 通过，TP=4、TN=6、FP=0、FN=0；漏桶算法回归 8/8 通过，TP=1、TN=7、FP=0、FN=0；ApacheBench 正常流量 5000 请求并发 50 无失败，规则命中流量 1000 请求并发 20 无失败；30 秒混合流量 2400 条请求全部通过，其中攻击 822 条、正常 1578 条；基础审计日志 25 行、批量/压测审计日志 1212 行、多 worker 审计日志 4 行、漏桶审计日志 1 行、混合流量审计日志 822 行均可被 Python 标准 `json` 模块解析。
- Docker 校验：`docker compose build` 成功；`docker compose run --rm litewaf-acceptance` 完成容器内最终验收，基础 65 条、reload 3 条、批量 400 条、ApacheBench 6000 次、混合流量 2400 条和 JSON Lines 日志硬性校验全部通过。

## 未来可能实现功能

- 增加共享动态封禁表的运行期观测接口，便于查看当前 IP 计数、封禁到期时间和淘汰情况。
- 扩展请求体检测的内容类型覆盖，例如 multipart 表单字段、上传文件名和更大 JSON 文档的分段观测。
- 增加外部访问控制文件加载、规则白名单、全局运行模式（仅记录、评分、阻断）等更细粒度运维接口。
- 为审计日志增加日志轮转适配和异步/缓冲写入，降低高并发场景阻塞风险。
- 增加更多规则测试样本和基准数据集，持续评估误报率、漏报率和性能开销。
- 增加 reload 压力测试和长期规则频繁变更测试，进一步观察长时间运行时的资源占用。
