## 2. 冻结口径

### 2.1 审计日志（14 字段，字段名不变）

```json
{"time":1792599126563,"client_ip":"127.0.0.1","method":"GET","uri":"/","reason":"rule_block",
 "rule_id":2001,"rule_name":"scanner user agent","zone":"USER_AGENT","category":"SCAN",
 "score":8,"total_score":0,"action":"deny","status":403,"cost_us":23}
```

- `time`：**UTC 毫秒整数**（epoch ms），方便采集直接落 `event_time_ms`；展示层按 Asia/Shanghai 渲染。
- `category`：保留引擎原值 `SQL/XSS/RFI/TRAVERSAL/EVADE/UPLOAD/SCAN`，CC 事件 `reason=dynamic_block` 且 `category` 为空。
  **展示映射（SQL→SQLi、dynamic_block→CC、blacklist→访问控制）在采集/后端适配层做，不改源日志**（需求卡片 §2.2 第 2 条）。
- `cost_us`：从 `ACCESS_PHASE` 进入 handler 起算到日志写出，**含异步 BODY 等待**，不是纯匹配耗时。
- 日志逐条 `open/write/close`，因此 `rename` 轮转天然可用（下次 `open` 自动建新文件）。

### 2.3 打分机制：按命中次数计分（2026-10-24 起）

引擎对每条规则统计「这次请求里命中了几次」，按次数乘分，单条规则封顶 `LWAF_MAX_HITS_PER_RULE = 3` 倍：

| 场景 | 改之前 | 改之后 |
|---|---|---|
| `/?id=1 UNION SELECT password FROM users` | `union select`（1005）命中 1 次 → 8 分 → 拦 | 同左 |
| `/?id=1 SELECT * FROM users` | `select`/`from` 都命中 1000 号，但只算 4 分 → **放行** | 命中 2 次 → 8 分 → **拦** |
| `/?x=select from where delete` | 4 分 → 放行 | 4×3（封顶）= 12 分 → 拦 |

- 分母仍按「规则条数」算，同一规则多次命中在审计日志里 `score` 字段就是**已乘过的贡献分**（例如 1000 号贡献 8 表示命中 2 次）。
- 代价：每条规则最坏多跑 2 次匹配，soak 的 P95 从 989µs 涨到 3076µs（79.97 RPS 下仍有 3ms 余量）。
- 评估效果：201 条样本 SQLi 检出 **46/50 → 48/50**，正常误拦仍为 0/101。

### 2.4 请求体上限（`lite_waf_max_body_bytes`）

| 项 | 值 |
|---|---|
| 指令 | `lite_waf_max_body_bytes <bytes>`（main/server/location，默认 8192） |
| 行为 | 有 `Content-Length` 且超限 → **直接 413**，审计日志 `reason=body_too_large` |
| 为什么 | 旧行为是「截断后只查前 8KB」，攻击者垫 8KB 填充即可让整段 payload 不被检测 |
| chunked | 无 `Content-Length` 无法预判，退化为截断检测（限制仍为 `LWAF_MAX_CAPTURE_BODY`） |

需要放行大表单的 location，显式调大该值即可，例如上传接口 `lite_waf_max_body_bytes 1048576;`。

## 5. 已知坑（复现时别再踩）

1. **`ngx_http_lite_waf_module/config` 必须 LF**，否则 configure 生成的 `objs/Makefile` 里路径带 `\r`，编译必然失败。改完 config 要 `rm -rf .../nginx-$VER` 重新 configure（旧 `objs/Makefile` 会缓存坏路径）。
2. **裸 `curl` 会被规则 2001（SCAN）拦**。测正常请求必须带浏览器 UA，否则看到的 403 是 UA 命中扫描器规则，不是误拦。
3. nginx 1.24.0 需要 `libcrypt-dev`；1.31.1 不需要，但 1.31.1 的 `auto/make` 对 addon 子目录规则处理不同，优先 1.24.0。
4. 源码里没有 `ngx_int64_t`，时间戳类运算用 `int64_t`。
5. `run_final_acceptance.sh` 默认前缀是 macOS 的 `/private/tmp/*`，Linux 必须导出 `WORK_DIR`/`BASIC_PREFIX`/`VOLUME_PREFIX`/`RELOAD_PREFIX`/`SOAK_PREFIX`/`MULTIWORKER_PREFIX`/`LEAKY_PREFIX`（`s0_build.sh` 已导出前 5 个）。
6. 虚拟机磁盘出现过物理坏块（`critical medium error` / `Sense Key : Medium Error`），关机必须 `sudo poweroff`，别用「关闭虚拟机电源」。
7. **跑 201 条样本评估时 `--gap` 必须 ≥ 0.7 秒**。0.4 秒时漏桶净增速率是正的（1/0.4 − 2 = +0.5 个/秒），80 秒后 `127.0.0.1` 会被 CC 封禁，后面所有正常样本一律 403，看起来像「误报率 100%」——实际上是把自己封了。症状是报告里 `CC：第 1 次开始 403`。
8. 改完模块要 `systemctl restart litewaf-runtime` 才生效（`reload` 不会重载二进制）。重启顺带清空漏桶封禁状态。
9. **规则行前缀是 `lwaf_rule`**，Nginx 指令才是 `lite_waf_*`。用 `grep -c '^lite_waf_rule'` 统计规则条数会得到 0，别据此判断「规则没加载」。
10. **CC 的漏水现在按毫秒算**（`lwaf_ip_stat_t.last_seen_ms`）。结构体是追加字段，reload 继承旧共享内存时该字段为 0，会退回秒精度并在下一次请求写回毫秒值——所以升级后第一轮若是旧槽位，仍可能有一次跨秒抖动，属正常。
11. 编译目录属主是 root，用 `kali` 用户直接 `make` 会报 `can't create objs/addon/src/*.o: Permission denied`，必须 `sudo bash scripts/s11_rebuild_engine.sh`。
12. 模块用了 `-Werror`，删掉不再调用的函数（比如 `lwaf_contains_lower`）不会报错，但**留着不用会编译失败**（`-Werror=unused-function`）。
