# 提升方案：检测率与监控预警

> 目标：把「未见过的攻击样本」检出率从 37.8% 拉到工业可用水平，同时把监控预警补齐到课件第 8 讲的要求。
> 不含时间压力，按依赖顺序排；每个阶段都有可复跑的验收口径。

---

## 第一部分：检测率

### 1.1 现状与诊断

| 口径 | 现状 | 说明 |
|---|---|---|
| CRS 公开样本（承诺类别 1173 条） | **37.8%** | SQL 34.15% / XSS 54.07% / 遍历 32.81% / RFI 42.42% / 扫描器 16.67% |
| CRS 公开样本（全部 2282 条） | 25.33% | 含 1109 条 RCE/PHP 注入，引擎不承诺 |
| 自建千条样本（1494 条） | 99.01% | 训练集，不能当泛化能力 |
| CRS 正常样本误拦 | 8.28% | 偏高 |

**根因**：检测方法是「82 条正则黑名单」——只认字面形态。CRS 的 SQL 检测核心是 libinjection（把 payload 解析成 SQL 词法单元序列，判断语法结构是否像注入），遇到编码、注释拆词、函数混淆时正则的形态特征全断，而语法结构还在。

**结论**：继续堆正则最多到 50%，且误报与维护成本指数上升。要突破必须换检测方法。

### 1.2 路线（按价值排序）

#### A. 检测预处理层（所有规则受益，先做）

现在的问题：
- 宽字节注入（`%bf%27`）→ URL 解码后是非法 UTF-8，引擎直接跳过匹配 → 11 条样本恒漏
- 只解码一次 → 双重编码、Unicode 转义漏
- 没有路径规范化 → `/a/../b` 这类既可能误报也可能漏

方案：在 `lwaf_build_request_context` 里加一个规范化管线：

```
原始值 → URL 解码 → HTML 实体解码 → Unicode(\uXXXX) 解码 → 全角转半角
      → 去 NUL → 路径规范化（./ .. // → 单斜杠）
```

每个字段同时保留「原始」和「规范化后」两份，规则可以按 zone 选匹配哪份（新增 `zones_raw` 属性）。
非法 UTF-8 时不去跳过，而是按字节匹配（PCRE2 加 `PCRE2_MATCH_INVALID_UTF` 或干脆不用 UTF 模式）。

**验收**：11 条宽字节样本全部命中；`/docs/../about` 这类正常路径不再被误判。

#### B. 接入 libinjection（核心，SQLi/XSS）

libinjection 是开源的纯 C 库（GitHub `libinjection/libinjection`），三个文件：

| 文件 | 作用 |
|---|---|
| `sqli.c` | SQL 注入语义检测，返回 1/0 + 指纹（如 `s&sos`） |
| `xss.c` | HTML5 tokenizer，检测 XSS 结构 |
| `html5.c` | 上面两个的公共依赖 |

接口极简：

```c
int libinjection_sqli(const char *s, size_t len, char fingerprint[8]);
int libinjection_xss(const char *s, size_t len);
```

集成点：在 `lwaf_evaluate_request()` 跑规则之前加「语义检测层」：

```c
/* 语义检测：对 URL+ARGS+BODY 拼接后的串跑 libinjection，
   命中则注入一条合成 match（类别 SQL/XSS、8 分、rule_name="libinjection"） */
if (conf->semantic_mode) {
    if (libinjection_sqli(buf, len, fp)) {
        add_synthetic_match(WAF_CAT_SQL, 8, "libinjection", fp);
    }
    if (libinjection_xss(buf, len)) {
        add_synthetic_match(WAF_CAT_XSS, 8, "libinjection-xss", "xss");
    }
}
```

要点：
- **不替换现有规则**，作为并行的一层；命中与规则命中一起进评分
- 性能：单次调用约 1–3 µs，一条请求最多 3 次（URL/ARGS/BODY），对比现在 82 条正则的 20–40 µs 可忽略
- 配置开关：`lite_waf_semantic on|off`（默认 on），出问题能一键退回

**预期收益**：CRS SQLi 34% → **75–85%**（CRS 自己就是 libinjection，理论上能追到它的水平）；XSS 54% → **70–80%**。

**风险**：libinjection 对「短参数」偏保守（比如 `?q=select` 单关键词不判注入），需要拿 676 条正常样本验证误报。

#### C. 路径穿越检测重写

现在是正则匹配敏感路径 + `..`。改为：
1. 规范化路径（A 阶段产出）
2. 白名单：以 `webroot` 开头的合法路径直接放行
3. 规范化后仍含 `..` 或在 webroot 之外 → 拦截
4. 保留现有规则作为兜底

**验收**：TRAVERSAL 32.8% → 60%+，且 `/docs/../about` 不再误拦。

#### D. 评分模型改进

现在是「固定分 + 阈值 8 + 命中次数最多 3 倍」。改为：

| 来源 | 权重 |
|---|---|
| libinjection 命中 | 8 分（单条即拦） |
| 高置信规则（语义明确的，如 `UNION SELECT`） | 6 分 |
| 弱特征规则（如 `0x`、`..`） | 2–4 分 |
| 同一规则多次命中 | 每多一次 +50%，上限 2 倍 |

规则文件加 `weight` 属性，`score=SQL:8` 保留但增加可选 `w=6`。

#### E. 误报控制

1. **白名单**：`lite_waf_whitelist` 扩展支持 URI 前缀、参数名、IP 段
2. **学习模式**：`lite_waf_mode monitor` 只记日志不拦，跑一周看误报
3. **误报回流**：已有 R34-10 的标记闭环，把标记过的样本自动加进回归集
4. **CRS 误拦压测**：676 条正常样本必须 ≤1%（现在 8.28%）

### 1.3 验收口径

| 指标 | 现在 | 目标 |
|---|---|---|
| CRS 承诺类别检出 | 37.8% | **≥65%** |
| CRS SQLi | 34.15% | **≥75%** |
| CRS XSS | 54.07% | **≥70%** |
| CRS TRAVERSAL | 32.81% | **≥60%** |
| CRS 正常误拦 | 8.28% | **≤1%** |
| 自建千条检出 | 99.01% | 不降（≥99%） |
| 单请求额外耗时 | – | **≤20 µs**（P95） |
| 14 步验收 | PASSED | 保持 PASSED |

### 1.4 需要下载的东西

| 文件 | 地址 | 大小 |
|---|---|---|
| libinjection 源码 | `https://github.com/libinjection/libinjection`（zip） | ~2 MB |

解压后把 `src/sqli.c`、`src/xss.c`、`src/html5.c` 三个文件放进 `WAF-lite/src/libinjection/`。

## 第二部分：监控预警（课件第 8 讲）

### 2.1 现状对照

| 课件要求 | 现状 | 要做 |
|---|---|---|
| 监控项的配置 | 只有「攻击类别 + 阈值」一个维度 | 扩展成多维：类别/IP/UA/关键词/状态码 |
| 阈值检测 | ✅ 已有 | 保留 |
| 突增检测 | ❌ 无 | 新增：窗口 vs 历史滑动均值比值 |
| 分级告警 | ❌ 无 | 新增黄/红两级 |
| 告警合并 | ⚠️ 抑制期合并 | 增强展示（聚合 N 条） |
| 通知渠道 | ⚠️ 只有 webhook | 加站内红点、邮件（接口）、渠道可配 |
| 告警确认 | ✅ 已有 handled | 保留 |
| 自动响应 | ❌ 无 | 红色告警 + 重复 → 自动封禁 IP |

### 2.2 设计

#### A. 监控项（`alert_rules` 扩展）

```sql
ALTER TABLE alert_rules
  ADD metric      VARCHAR(16) NOT NULL DEFAULT 'category',  -- category|ip|ua|keyword|status
  ADD match_value VARCHAR(64) NOT NULL DEFAULT '',          -- metric=keyword 时的关键词
  ADD ratio       DECIMAL(4,1) NOT NULL DEFAULT 5.0,        -- 突增倍数
  ADD severity    VARCHAR(8)  NOT NULL DEFAULT 'yellow',    -- yellow|red
  ADD channel     VARCHAR(16) NOT NULL DEFAULT 'webhook';   -- webhook|inapp|email
```

语义：
- `metric=category` + `match_value=SQL` → 现有行为（按攻击类别计数）
- `metric=ip` + `match_value=` → 单 IP 在窗口内的全部拦截数
- `metric=ua` + `match_value=sqlmap` → UA 含关键词的请求数
- `metric=keyword` + `match_value=union` → URI/UA 含关键词的请求数
- `metric=status` + `match_value=403` → 403 数量

#### B. 检测逻辑（两级）

**阈值检测**（已有）：窗口内 count ≥ threshold → 触发。

**突增检测**（新增）：
```
当前窗口 count ÷ (过去 1 小时同维度每窗口 count 的均值) ≥ ratio → 触发
冷启动保护：过去 1 小时有效窗口数 < 3 时不判突增
```

实现：一条聚合 SQL 就能算（`GROUP BY FLOOR(event_time_ms / window)`），不需要新表。

#### C. 分级

| 级别 | 条件 | 处置 |
|---|---|---|
| 黄（warning） | 达到阈值，或突增 5–10x | 只通知 |
| 红（critical） | ≥2× 阈值，或突增 ≥10x，或 ≥3 个不同来源同时超阈值 | 通知 + 可选自动封禁 |

#### D. 通知渠道

| 渠道 | 实现 |
|---|---|
| `inapp` | 前端左侧菜单红点 + 顶部 toast；后端 `/api/alerts/unread` 计数 |
| `webhook` | 已有，保留 |
| `email` | 走 `javax.mail` 或 Spring `JavaMailSender`，配置 SMTP；**本地环境没有外网 SMTP**，用 `mailhog` 容器或直接落 `.eml` 文件到 `/opt/litewaf/outbox/` 代替，文档写明生产接真 SMTP |

投递失败重试已有（`next_retry_ms` + 10 秒），保留。

#### E. 自动响应

```
红色告警 + 同一 IP 10 分钟内 ≥3 次红色告警
  → 调用执行器 POST /block {ip, ttl_s: 3600, reason}
  → 执行器写 /opt/litewaf/runtime/blocklist/<ip>.json
  → 生成 blocklist.conf 并 nginx -t + reload
  → 记录到 operations 表（可审计、可回滚）
```

module 侧加一条指令 `lite_waf_blocklist /opt/litewaf/runtime/blocklist.conf;`，文件格式：
```
192.168.1.5 1793600000;   # IP 到期时间戳
```
`lwaf_get_client_ip` 之后查一次（用共享内存缓存，worker 每 5 秒重载），命中直接 403。

#### F. 可观测性

新增「告警健康」卡片：
- 事件入库 → 告警触发的 P95 延迟（现在是 2 秒轮询，目标 <5 秒）
- 投递成功率、失败重试次数
- 过去 24 小时告警数按级别分布

### 2.3 验收

| 项 | 口径 |
|---|---|
| 突增检测 | 造一个 IP：前 1 小时每 5 分钟 1 条，当前 5 分钟打 8 条 → 触发黄（8/1=8x） |
| 分级 | 同上再叠加 3 个不同 IP → 升级红 |
| 关键词监控 | `?q=union select` 打 20 次 → 触发 |
| 站内通知 | 页面 3 秒内出现红点 + toast |
| 邮件渠道 | 落 `.eml` 文件到 outbox，内容含告警详情 |
| 自动封禁 | 红色告警 3 次后，该 IP 请求返回 403，且 1 小时后自动解封 |
| 告警延迟 | 事件入库到前端口显示 ≤ 5 秒 |

## 第三部分：执行顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P1** | 预处理层（规范化 + 非法 UTF-8 不跳过） | 无 |
| **P2** | libinjection 接入（SQLLi + XSS） | 需要下载源码 |
| **P3** | 路径穿越重写 + 白名单 | P1 |
| **P4** | 评分模型（权重） | P2 |
| **P5** | 监控项扩展 + 突增检测 + 分级 | 无（可与 P2 并行） |
| **P6** | 通知渠道（站内 + 邮件） | P5 |
| **P7** | 自动响应（blocklist + 执行器 /block） | P5、引擎指令 |
| **P8** | 告警健康卡片 + MISC | P5 |
| **P9** | 全量回归（CRS + 自建 + 14 步 + 15 项） | 全部 |

每个阶段结束都跑一次回归，避免「改一处坏一片」。

## 第四部分：明确不做

- **不做机器学习检测**：样本量不够（1500 条），且不可解释，答辩讲不清
- **不做多租户/分布式**：单机是课程范围
- **不追 RCE/PHP 注入**：不在承诺范围，硬做会拉高误报
- **不把阈值调到最低换检出率**：误报 8.28% 已经偏高，先降误报再加检出
